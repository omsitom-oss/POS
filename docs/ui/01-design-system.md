# Elite POS design system

All production screens use the shared visual foundation: tokens in `frontend/src/styles/tokens.css`, shared rules in `frontend/src/styles/system.css`, components in `frontend/src/components`, and `AppLayout`. The shell has a collapsible sidebar, a restrained header, and a flexible main area; Design Lab stays under Development.

Shared controls include Button/IconButton, form inputs, FormField/FormSection, DataTable, Card, Modal/ConfirmDialog, badges, and loading/empty/error states. Simple master-data add/edit tasks use centered modal dialogs. Pages should compose shared pieces and keep business behavior in their feature.

Elite POS displays one language at a time. English uses LTR; Arabic uses RTL. Bilingual fields appear together only while maintaining translated master data. The Settings home uses compact type cards, flat values use DataTable, and hierarchical values use card drill-down with clickable breadcrumbs, never a tree UI.

Use monochrome theme-following interface icons. Setting icons and ordering are not data-entry fields. Setting Code and SortOrder are generated by the backend. All new screens use the shared components and semantic tokens; do not create page-specific visual systems.
The application-wide UI font is the `--font-sans` token in `frontend/src/styles/tokens.css`: Segoe UI (which carries both Latin and Arabic on Windows), then `Simplified Arabic`, Tahoma and system fallbacks. All screens, controls, tables, dialogs, navigation, and bilingual master-data views inherit it. Document numbers in tables use the same font with tabular figures; only generated setting codes use `--font-mono`.

The visual direction and before/after screenshots are in `docs/design/review.md`.
