# Currencies

Currencies are a dedicated POS table because they have codes, symbols, financial meaning, and a primary-currency rule. Migration 005 creates `Currencies` with `CurrencyCode`, Arabic/English names, `Symbol`, `IsPrimary`, `IsActive`, and UTC timestamps. Migration 007 adds optional `FlagBase64` (`nvarchar(max)`) for a customer-uploaded flag image; the API accepts image data URLs up to 750 KB and returns the value for display. `CurrencyCode` is unique and generated by the backend from the identity (`CUR-{CurrencyId:D6}`, for example `CUR-000001`); clients do not supply or edit it, and renaming a currency does not change it. SQL Server's filtered unique index permits only one primary currency.

The API is `GET /api/currencies`, `POST /api/currencies`, `PUT /api/currencies/{id}`, rate updates at `PUT /api/currencies/{id}/rate`, and activate/deactivate actions. The Settings Currencies screen uses a bilingual maintenance modal and a shared table. Creating or editing a primary currency clears the previous primary inside a serializable transaction; the database index remains the final concurrency guard. Exchange-rate history is documented in [10-currency-rates.md](10-currency-rates.md).
